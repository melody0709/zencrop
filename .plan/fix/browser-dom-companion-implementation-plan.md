# 浏览器自动选框扩展化实施方案

> 日期：2026-10-13
>
> 状态：桌面、扩展、通信、部署与验证代码已实施（v3.2.0，未发布）；Chrome/Edge 开发几何与生命周期矩阵已运行，实机多屏/DPI、持续性能与正式发布验收仍未签收。详细状态和证据见 [实施验证记录](../../doc/browser-companion-validation.md)。
>
> 研究依据：[浏览器无障碍持续性能下降研究](browser-accessibility-dom-disconnect-research.md)。该文件保留为研究文档；实现范围、执行顺序和验收以本文为准。

## 1. 已确认的目标

**浏览器自动选框改用配套扩展直接获取网页元素位置；其他应用继续使用原有检测方式。**

用户所称“其他应用原来的 UIA 方案”，在当前代码中应理解为“原有系统无障碍检测路径”。当前 SmartDetector 的主要命中与层级遍历使用 MSAA / IAccessible，浏览器预热额外调用 UIA。本次不得把非浏览器改写成另一套 UIA 实现。

交付后的行为：

| 目标 | 自动选框来源 | 不可用时的行为 |
|---|---|---|
| 已安装并授权扩展的受支持浏览器普通网页 | 扩展 DOM 几何 | 窗口选框或手动框选 |
| 未安装扩展、未授权、断连、受限页面 | Win32 窗口几何 | 窗口选框或手动框选 |
| 其他应用 | 原有 MSAA 等检测路径 | 保持原有降级 |
| 浏览器工具栏、内部页、无法进入的嵌套表面 | Win32 窗口几何 | 手动框选 |

**硬边界：浏览器选框不得在扩展失败时重新调用 UIA/MSAA。** 这条规则同时约束悬停、滚轮父/子导航、初次预热、重连与冷启动，避免把持续性能问题作为隐藏兜底带回来。

本方案消除的是“浏览器自动选框引发的无障碍开销”。其他辅助工具或 ZenCrop 划词翻译仍可能开启浏览器无障碍，不能扩大承诺成“任何情况下 Chrome 都不会开启 AX”。

## 2. 范围与首批支持

### 2.1 本次必须完成

- 浏览器与非浏览器分流，覆盖所有自动选框入口。
- Chrome、Edge 的 Manifest V3 配套扩展。
- 官方 Native Messaging 到桌面端的可靠通信与注册。
- 沿用 ZenCrop 桌面快捷键启动，不要求每次先点击扩展按钮。
- 普通网页的悬停命中、矩形、滚轮父/子候选。
- 同源和已授权跨域 iframe、可访问 Shadow DOM 的命中与坐标处理。
- 会话取消/结束、断连、导航与过期回复处理。
- 单屏/双屏、负坐标、混合 DPI、网页缩放的实机验收。
- 浏览器退出选框后不留下本功能的检测工作，非浏览器行为保持。
- 开发安装说明，以及正式安装/升级的交付方式。

### 2.2 首批支持边界

正式签收先覆盖 Windows 上的 Chrome 与 Edge；其他 Chromium 浏览器可在验证其扩展安装、Native Messaging 注册和坐标后纳入。

现有 BrowserWhitelist 还包含 Firefox 等非 Chromium 浏览器：这些已识别浏览器也必须受“不调用浏览器无障碍”的保护。首批没有兼容扩展时提供窗口/手动选框，不宣称已支持它们的 DOM。

浏览器分类复用既有进程名名单，并结合已有窗口发现能力；已登记的扩展连接可补充确认目标身份。未知、改名或无法确认身份的浏览器须在支持清单与测试中显式登记，不能承诺仅凭旧名单覆盖所有浏览器。

Electron/WebView 嵌入应用不按“任何 Chromium 内核进程”一律屏蔽。它们默认属于其他应用，除非后续明确登记为受支持浏览器目标。

### 2.3 本次不扩展的内容

- 划词翻译、网页文本提取、翻译扩展或 OCR 引擎。
- 视觉选框算法、调试端口、debugger 权限与修改浏览器启动参数。
- 自动操作 chrome://accessibility 或关闭用户的辅助工具。
- PDF/Canvas/WebGL 内部对象的通用识别。
- 与问题无关的设置页面重构、全仓格式化、架构 Stage。
- 商店发布与 MSI 实际安装/升级操作；先完成可审查产物与验证，发布阶段单独执行。

Chrome 内部页、扩展商店等受限页面及浏览器工具栏的降级属于明确支持边界。普通按钮、输入框和文本段落的 DOM 精度不能以窗口降级代替验收。

## 3. 方案决策

### 3.1 通信选 Native Messaging

通信链：

```text
ZenCrop 现有选框遮罩
       ↕ 会话开始/结束、查询、结果
L1 检测侧：浏览器分流与候选框状态
       ↕ 当前用户本地命名管道
本地 Native Messaging host
       ↕ 官方长度前缀 JSON 管道
扩展 service worker：目标与 frame 路由
       ↕ 扩展消息
目标网页 content script：DOM 命中与矩形
```

不为本功能改造 MiniHttpServer。当前它是图片 GET 服务，缺少 WebSocket 支持；新建网页长连接与通用本地端口也不是本任务必需。

Native Messaging 使用 runtime.connectNative 建立连接，不按每次鼠标查询使用 sendNativeMessage 反复启动进程。content script 的消息必须经过 service worker。[Chrome 官方协议与访问限制](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging)

### 3.2 主程序复用 EXE，入口必须前置

优先复用 ZenCrop.exe 作为受限 native host 进程，避免第一版增加独立 EXE 与另一套部署链。

Chrome host manifest 的 path 是程序路径，不能假设能在其中拼接“EXE + --native-host”参数。浏览器会传入调用扩展 origin，因此实施方式为：

1. 在 wWinMain 现有参数解析后、单实例 mutex 和桌面初始化之前，识别 Native Messaging 调用。
2. 校验首个 origin 是否为登记的扩展 ID，并校验继承标准输入/输出句柄。
3. 进入专用 L1 host 函数，只转发受限协议；不创建托盘、窗口、热键、模型或 UIA 客户端。
4. 使用 GetStdHandle 和二进制 ReadFile/WriteFile 处理 stdio，不创建可见控制台；stdout 不写日志。
5. EOF、协议非法或管道断开时退出 host 模式，不转入普通应用模式。

入口分支必须在单实例检查前，否则桌面 ZenCrop 已运行时 native host 会直接被拒绝。若实测发现 GUI EXE 的继承管道不能可靠工作，再裁决独立小 host；不得在未验证前同时维护两套实现。

origin 与标准句柄校验是调用检查，不是对本机同用户程序的完整认证。桌面 IPC 仍需当前用户访问控制与进程身份校验。

### 3.3 桌面全局热键决定权限方案

为保留当前桌面快捷键，使用用户一次授予的 HTTP/HTTPS 站点权限，以及被动 content script。首版可采用 http://*/*、https://*/* 的静态脚本匹配；安装界面必须准确解释“读取网页元素位置”需要站点访问权。

不宣称 activeTab 足够：桌面全局热键和 Native Messaging 消息不会自动授予 activeTab。只用 activeTab 的体验需要浏览器侧按钮或 commands 快捷键启动，与当前决定不同。[activeTab 官方触发规则](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab)

content script 支持 all_frames 与相应相关 frame 规则，并使用隔离世界；不注入页面主世界、不执行远程代码。

### 3.4 保留待机桥，停止网页检测

桌面端不能凭空唤醒已休眠的扩展 service worker。第一版采用扩展启动/用户启用时 connectNative，并保持一条被动控制连接，供桌面快捷键发送会话指令。

这会保留 native host 进程与 service worker；**不能承诺整个扩展平时完全休眠或零内存占用。** 官方说明 native connection 可以延长 service worker 生命周期。[官方生命周期说明](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)

不选框时要求：

- 页面无 DOM 扫描、几何轮询、MutationObserver、活动定时器或动画帧循环。
- host 与 worker 在消息/管道上等待，不用心跳轮询保活。
- 桌面应用未运行时，host 可阻塞等待其 IPC 可用，不自动启动桌面功能。
- 断开后的恢复通过有界退避或生命周期事件处理，不能紧密重试；用户可通过扩展操作显式重连。
- 待机桥按浏览器 profile 保持；只激活目标连接，不能把光标查询广播到所有网页。

待机 CPU、内存与页面基准必须实测；“无网页检测工作”与“没有后台进程”是不同验收项。

具体新文件名在实施时按最小责任定稿。检测与通信放入既有 L1 目录，不为扩展新增 src/ 子目录或提高架构基线。

### 4.1 根层防线

在 EnsureAccessibleRoot 对“浏览器”先拒绝，比只在 UI 层避开调用可靠；浏览器分流在 GetRectByPoint / GetParentRect / GetChildRect 提前进行。

移除仅用于浏览器的 WarmBrowserMsaa、遮罩打孔 UIA 预热及其缓存；删除前检查全部调用。非浏览器路径不因该删除换协议或改变策略。

Window/客户区降级只用 Win32 窗口几何，不用无障碍“试一下”。浏览器类型判定、边界矩形和目标存活检查都应先于扩展数据应用。

### 4.2 会话与响应身份

检测 owner 维护 Idle → Active → Ended 的会话代际。每条查询和回复至少包含：

- 协议版本、sessionId、递增 requestId；
- 连接/profile 身份与目标 window/tab/document/frame 身份；
- 几何版本或失效代际；
- 状态、CSS 矩形、必要的坐标转换元数据。

上述浏览器身份取自扩展 API 与 message sender，不接受页面自己声明的 tab/frame 权威。

离开 Hover 开始确认/拖拽、取消、结束、切换目标、导航或窗口消失时，旧代际结果必须失效。UI 线程应用前再核对当前会话与请求，不能只依靠后台过滤。

鼠标移动只保留最新待处理查询；滚轮导航按当前候选有序处理，不把全部滚轮命令当鼠标移动合并丢弃。

## 5. 浏览器目标与坐标：第一阶段必须过的难点

### 5.1 先绑定目标，再取元素

截图遮罩出现后，lastFocusedWindow 可能不再代表要截图的浏览器。扩展服务 worker 的 --parent-window 也可能为 0，不能用它作为唯一 HWND 来源。

应在遮罩覆盖前捕获底层目标快照，并由桌面 Win32 窗口发现与扩展窗口信息建立绑定；之后鼠标跨窗口时重新绑定。绑定需包括浏览器实例/profile、HWND、windowId、active tab 与 document。

原型必须验证 native host 与启动浏览器的身份关联，以及窗口 bounds/状态等信息能否确定对应 HWND。标题文本不得成为唯一依据。

多个 profile、相同标题/URL、并排浏览器、后台目标或绑定歧义必须明确处理；无法唯一确定就返回 target_unavailable，不能任选一个窗口或查询全桌面。

### 5.2 坐标转换要求

桌面使用物理屏幕坐标；content script 使用 frame 视口 CSS 坐标。完整转换需处理：

- 浏览器网页视口原点与物理范围；
- Windows DPI、网页缩放、devicePixelRatio；
- iframe border、滚动、transform 与嵌套链；
- visualViewport 偏移/缩放与页面滚动；
- 负坐标屏和跨不同 DPI 显示器；
- 工具栏、侧栏、DevTools 停靠、最大化与全屏。

可把已发现的 Chrome_RenderWidgetHostHWND 作为视口几何候选，必须校验存在、归属与映射，不能把内部类名当永远存在的公共契约。不用 UIA 校准坐标。

**完成条件是实测转换准确；一条 ScreenToClient / DPR 公式不是验收。** 若原型不能在普通单窗口可靠绑定和换算，应停在该阶段修正映射，不能用重新启用浏览器无障碍绕过。

### 5.3 与冻结截图一致

截图模式已经捕获冻结帧。会话开始时记录几何快照，命中后缓存当前候选路径；不在后台网页不断变化时无限刷新并把新位置套到旧图。

扩展在活动期记录导航、视口变化和 DOM 变化造成的几何失效；按需设置轻量失效观察，结束时移除。它只能帮助检测变化，不能证明所有动画/字体/布局都静止。

发现失效时优先丢弃候选并降级，不能继续展示明显错误框。首版不做全页 DOM 镜像或自动重截屏；动态页面的截图与 DOM 快照之间仍可能有时间差，纳入实机验收与说明。

普通非冻结选框模式按当前页面几何更新；不套用冻结截图的长期缓存。

## 6. DOM 候选与滚轮语义

- document.elementFromPoint 命中后，按需进入 iframe / ShadowRoot；只查询当前目标链。
- 使用 getBoundingClientRect 获取元素边界，裁剪到允许的视口与截图范围。
- 小于有效面积、非有限数、越界或不含查询点的回复拒绝。
- 沿 composed ancestry 收集有意义的父级，去掉相同矩形；ShadowRoot 跨 host、slot 与 iframe 边界显式处理。
- 滚轮向上从当前候选转向包含它的更大父级；向下沿当前鼠标命中路径返回较小候选，不能任意取第一个 DOM child。
- 内联多行文本按实际需求使用 getClientRects 或段落包围框，明确语义；不为本文增设富文本编辑或 OCR。
- 命中精度与行为以现有用户操作体验验收，不承诺 DOM 父级与视觉分组一一对应。

活动会话结束后释放元素引用与候选路径；页面导航后不复用旧 DOM 节点。普通 JS 几何读取可能触发布局，需批量读、限频与测量。

## 7. 最小协议、失败处理与信任边界

仅需要 hello、begin、inspect、navigate、end，以及 result / unavailable / invalidated。不要加入执行脚本、读取任意文件、截取任意文本或通用远程命令。

状态至少区分：未连接、未授权、受限页面、目标不明、超时、几何失效、版本不兼容。UI 可归并为简短提示；技术原因进入诊断，不能在每次鼠标移动弹窗。

- Native Messaging 的长度前缀与 UTF-8 JSON 严格校验；处理分段读取/写入和 EOF。
- 本功能单条消息限定 64KiB，候选上限 64；超过即拒绝，不根据外部长度无限分配。
- 大整数身份用字符串或明确安全范围；矩形允许负坐标，但必须有限、范围合理且可安全转换。
- allowed_origins 固定到开发/正式登记的扩展 ID；不会允许任意扩展。
- service worker 验证 sender 与已绑定文档，不桥接未经校验的 window.postMessage。
- 命名管道按当前用户 SID 和会话隔离、拒绝远端、核对连接进程；不新增管理员权限要求。
- 单个不完整消息不能阻塞所有连接；取消/退出应能中断管道等待。
- 查询预算首版 100ms，超时保持窗口/手动操作可用；UI 不等待桥回复。
- 会话结束先在本地作废再发送 end；扩展另有可续期的活动会话期限，避免丢失 end 后留下观察/任务。
- 不记录正文、密码框值、Cookie；性能诊断仅保留必要身份、状态、尺寸和时间，默认不记录完整 URL。
- 同用户恶意本地程序不属于完整防护承诺，但必须避免任意网页借桥触发桌面特权操作。

250ms 内结束会话是本次取消/关闭的验收目标；活动租约兜底时限在原型中测量后固定，不以它代替正常 end 清理。

## 8. 安装、注册与交付

开发阶段先提供可解压加载的扩展与准确的 host 注册/取消步骤。保持扩展 ID 稳定，开发 ID 与正式商店 ID 分开登记。

Windows Chrome 和 Edge 的 Native Messaging 注册位置分别依据官方文档；其他浏览器不能假设共用注册键。开发注册只操作本功能自己的键和值，记录原值，不覆盖未知已有配置。

正式 MSI：

- manifest/payload 通过 CMake install 进入唯一运行目录，不能手工复制到 build/run。
- host manifest 使用已安装位置的正确程序路径；支持非默认安装根与空格路径。
- 注册键和值由 WiX 精确 Component 拥有；不以 custom action 写/清其他目录。
- 升级与卸载准确维护自身注册，保留用户数据与未知文件。
- 不改固定 UpgradeCode / namespace；payload 或安装语义变化需提升三段版本。
- 构建、静态验证和 msiexec /a 与正式安装矩阵分开；不得在日常构建中真实安装/升级。
- 移动便携目录会导致注册路径失效，提供显式重新注册/取消；不能擅自创建 portable.flag。

扩展图标等新资产若引入，记录来源与许可证；首版不为功能采购或引入第三方依赖。

## 9. 实施顺序与阶段完成条件

### P1：最小通路原型

完成 Chrome 普通单页 → native host → 当前用户 IPC → 桌面检测的闭环，先证明一个按钮的准确矩形与目标绑定。

同时验证复用 EXE 的 host 入口、stdio、桌面已运行时连接、站点权限、单窗坐标、连接待机成本。此阶段可用开发夹具，不把扩展缺失时的窗口降级当成功。

完成条件：目标不歧义、矩形准确、无 UIA/MSAA 浏览器调用，结束后无活动网页检测。若映射或桥失败，继续解决它，不扩大功能。

### P2：生产分流与生命周期

在共享检测层加入浏览器防线，删除浏览器预热，集成现有遮罩和异步返回；补父/子导航与过期结果过滤。

完成条件：无扩展、冷启动、断连与滚轮均不触发浏览器无障碍；原有非浏览器用例通过；取消与关闭在预算内。

### P3：复杂网页与坐标

完成同源/授权跨域 iframe、Shadow DOM、嵌套祖先候选、滚动/缩放/导航失效、多窗口/profile 与多屏 DPI。

完成条件：第 10 节核心几何矩阵通过；受限页清楚降级；不能准确绑定的目标安全拒绝。

### P4：部署与实机性能签收

完成 Chrome/Edge 注册、开发说明、正式安装资产与版本处理；跑阶段相关测试、增量构建和真实浏览器性能对照。

完成条件：性能与操作矩阵通过并记录证据。代码通过构建仅能标“实现完成”，不得标“性能问题已修复”或“实机已签收”。

商店发布、正式 MSI 升级 VM 矩阵按发布契约另行执行；未做时明确保留未签收项。

## 10. 验证清单与验收指标

### 10.1 自动化验证

复用 test_screenshot_editor_state_contract 等现有目标验证会话代际、目标切换、失效结果与导航语义；若需覆盖 L1 纯协议/几何，给合适的既有目标链接 zencrop_platform。

不新增小功能专用 C++ test executable，不把 src cpp 列进测试；不加 test-only production API。能独立输入的协议解析、映射和候选归一逻辑通过真实库入口测试。

扩展用可复现网页夹具与断言脚本验证 DOM 候选；夹具按实例/PID 隔离，记录正反例。不得用真实私人页面作为公共夹具。

必须覆盖：

- 浏览器三入口全拦截与非浏览器旧路径保留。
- 分段消息、非法 UTF-8/JSON、超长帧、EOF、未知版本。
- 错 session/request/document、取消后晚到回复。
- 两 profile/窗口歧义、非法坐标、空矩形。
- 滚轮父/子一致、iframe/Shadow 边界与几何失效。
- 断连、重连与丢失 end 的清理。

### 10.2 实机操作矩阵

| 场景 | 期望 |
|---|---|
| Chrome、Edge 普通按钮/输入框/段落 | 准确命中，滚轮层级可用 |
| 未安装/禁用扩展、站点未授权、host 未注册 | 可继续窗口/手动框选，无浏览器 UIA/MSAA |
| 内部页、工具栏、PDF/Canvas 不支持的内部对象 | 有明确边界，不错误宣传 DOM 穿透 |
| 同源与已授权跨域 iframe、Shadow DOM | 正确命中和祖先转换；未授权 frame 明确降级 |
| 100/125/150/200% 系统缩放；80/100/125/150% 网页缩放 | 框与目标吻合，不混用 CSS/物理像素 |
| 双屏、左侧负坐标、混合 DPI、跨屏移动 | 转换与会话更新正确 |
| 侧栏、DevTools 停靠、最大化、全屏 | 视口原点正确 |
| 相同标题/URL的多窗口、多 profile、Chrome 与 Edge 同开 | 结果属于当前目标，不能串窗口 |
| 选框中导航/滚动/窗口移动/页面动画 | 失效时不套用错误旧框 |
| 快速移动、连续滚轮、反复截图/取消、关闭桌面/浏览器 | 无过期框、无挂起、无残留活动检测 |
| 原生应用文本、列表、工具栏与原有降级 | 保持修改前体验 |

### 10.3 性能验收

用户已证明旧方案存在持续回归，不反复重做问题证明。新的验收至少区分：

1. 新浏览器会话干净基线。
2. 扩展已安装、桥已连接但没有选框。
3. 扩展选框工作期间。
4. 选框完成和取消后的同一浏览器会话。
5. 多次选框后的同一会话。

开始时记录 AX 状态与其他辅助工具。性能测试期间不使用会触发 AX 的 Inspect/UIA 自动化/无障碍树检查；不点击 Show/Refresh tree。若需要调试自动化，所有组用相同条件，且不启用 Accessibility 域。

- 基准每组至少 5 次，记录中位数与波动；不要硬要求“恰好 52 分”。
- 待机及结束后组应落回测得的基线波动范围；暂用 5% 相对差作为调查阈值，不能把高噪声误判成通过。
- 同时观察浏览器与桥 CPU，不只看 ZenCrop 已停止。
- 热态桌面请求到选框呈现的 p95 目标为 25ms；冷启动另记，不拿 JS 单函数耗时代替端到端。
- 取消/结束后 250ms 内本地会话失效与正常清理完成；丢失 end 按租约兜底单独测。
- 记录待机 host/worker 内存与 CPU，不写“完全休眠”“零损耗”。
- 已被旧路径开启 AX 的会话不能直接拿来验收新路径恢复；新路径主要防止新增触发，不承诺撤销历史状态。

若新路径没有触发 AX，但退出后仍有稳定性能差异，就排查扩展任务和桥生命周期，不通过放宽阈值签收。

### 10.4 仓库验证与证据

实现阶段按变更范围运行：

- 产品：cmd.exe /d /c build.bat，由其执行架构守卫与 install。
- 直接相关既有测试：cmd.exe /d /c tests\build_and_run.bat <test_name>。
- 检查现有 smoke_zencrop_platform 的独立链接；跨 IPC/生命周期变更补相应检查。
- 输出：测试进 build/artifacts/tests，诊断进 build/artifacts/diagnostics，日志进 build/logs。
- 最终源码未再变时不重复构建；交付前 git diff --check。
- 本次新增验证脚本采用 pwsh 7，build/test 调用的 ps1 保持 ASCII；源码读取 UTF-8。

实机证据应包含版本、用例、样本和失败原因。不得以默认门通过替代多 DPI 或浏览器性能验收。

## 11. 回退与最终交付标准

回退不允许静默恢复浏览器无障碍检测。桥或扩展失效时保持浏览器窗口/手动框选；非浏览器原有检测不受影响。

删除/取消注册只触及本功能精确拥有的项；便携与已有注册需保留恢复信息。不会改动浏览器 flags、用户 profile、浏览器启动方式或辅助工具设置。

最终交付应同时提供：

- 可审查的桌面变更、扩展源码、注册资产与安装说明。
- 自动化验证结果、Chrome/Edge 实机矩阵与性能证据。
- 已支持/降级页面范围、待机成本与已知动态页面限制。
- 明确状态：实现完成、开发验收完成、发布验收完成分别记录。

**实施已落地，非浏览器保留原实现。自动化与浏览器开发矩阵通过不等于全部实机或性能验收通过；P4 的持续性能、物理硬件及正式发布矩阵仍待签收，详见 [实施验证记录](../../doc/browser-companion-validation.md)。**
